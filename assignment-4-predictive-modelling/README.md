# Assignment 4 — Predictive Modelling with Pandas (Titanic)

An end-to-end machine learning pipeline built with **pandas**, **matplotlib** and
**scikit-learn**. It ingests the Titanic passenger dataset, cleans it, explores
it, trains a Logistic Regression classifier, evaluates it honestly on unseen
data, and predicts survival for brand-new passengers.

Every module is written to be read: the code is deliberately over-commented so
the pipeline doubles as a tutorial.

---

## Quick start

```bash
# 1. Install the dependencies
pip install -r requirements.txt

# 2. Run the entire pipeline
python main.py
```

Run it **from inside the `assignment-4-predictive-modelling` folder** — the data
path (`Data/train_and_test.csv`) and the output paths (`plots/`,
`Data/titanic_cleaned.csv`) are all relative to the working directory.

> Execution **pauses** at each one until you close the chart window. That is
> expected behaviour, not a hang.

## The seven phases

| Phase | What it does | Entry point |
|-------|--------------|-------------|
| **1** | Load the CSV; print head, shape, `info()`, columns, missing values | `preprocessing.load_and_explore_data()` |
| **2** | Drop junk columns, fill missing values, rename, one-hot encode, save | `preprocessing.clean_data()` |
| **3** | Descriptive stats, grouped survival rates, correlations, 7 charts | `eda.run_eda()` |
| **4** | Keep genuinely-labelled rows, split X/y, train-test split, scale | `preprocessing.prepare_model_data()` |
| **5** | Train Logistic Regression; compare candidates via cross-validation | `train.train_model()` |
| **6** | Accuracy, confusion matrix, classification report, overfitting check | `evaluate.evaluate_model()` |
| **7** | Predict for 6 invented passengers, with probabilities and a manual trace | `predict.predict_samples()` |

## About the dataset

`Data/train_and_test.csv` is a pre-processed variant of the classic Titanic
dataset — **not** the standard Kaggle file. Its header is:

```
Passengerid, Age, Fare, Sex, sibsp, zero × 19 …, Parch, Pclass, Embarked, 2urvived
```

Quirks and how the pipeline handles each:

| Quirk | Handling (Phase 2) |
|-------|--------------------|
| 19 columns literally named `zero` (pandas suffixes them `zero.1` … `zero.18`) | Verified to sum to 0, then dropped |
| Target column is misspelled `2urvived` | Renamed to `Survived` |
| `sibsp` is lowercase while `Parch`/`Pclass` are not | Renamed to `SibSp` |
| `Passengerid` is just a row counter 1…1309 | Dropped — an ID has no predictive value |
| `Embarked` has 2 missing values | Filled with the mode, then cast back to `int` |
| `Sex` is binary 0/1 | Left as-is — no false ordering is possible |
| `Pclass` is ordinal 1/2/3 | Left as-is — the ordering is genuine |
| `Embarked` is nominal 0/1/2 | Mapped to `C`/`Q`/`S`, then one-hot encoded with `drop_first=True` |
| No `Name`, `Ticket` or `Cabin` columns | Not present in this variant |

Column meanings:

```
Survived : 0 = died, 1 = survived            <-- TARGET
Pclass   : ticket class  1 = 1st, 2 = 2nd, 3 = 3rd
Sex      : 0 = male, 1 = female
Age      : age in years
SibSp    : siblings / spouses aboard
Parch    : parents / children aboard
Fare     : ticket price paid
Embarked : port boarded  0 = Cherbourg, 1 = Queenstown, 2 = Southampton
```

### ⚠️ Important data-quality finding

The file is Kaggle's `train.csv` (891 rows, **real** labels) stacked on top of
`test.csv` (418 rows whose labels are **deliberately hidden**). Whoever built it
filled those 418 unknown labels with `0` — so the data claims all 418 of those
passengers died. That is not true; their outcome is simply unknown.

**Phase 4 therefore keeps only the first 891 rows** (`data.iloc[:891]`).
Training on fabricated labels would teach the model a false pattern and inflate
the apparent accuracy.

Final feature set (8 features + target):

```
Age, Fare, Sex, SibSp, Parch, Pclass, Embarked_Q, Embarked_S  →  Survived
```

`Embarked_C` is the dropped baseline: `Q=0, S=0` means Cherbourg.

`random_state=42` is fixed for both the split and the model.

| Metric | Value |

| Rows used for modelling | 891 (of 1309) |
| Train / test split | 712 / 179 (80 / 20, stratified on `y`) |
| Model | Logistic Regression (`max_iter=1000`) |
| Baseline (always guess "died") | 61.62 % |
| **Test accuracy (unseen data)** | **80.45 %** |
| Improvement over baseline | **+18.83 percentage points** |
| Train vs test gap | 0.31 pp → no overfitting |

**Confusion matrix (179 test passengers):**

|  | Predicted: Died | Predicted: Survived |
|---|---|---|
| **Actual: Died** | 98 (TN) | 12 (FP) |
| **Actual: Survived** | 23 (FN) | 46 (TP) |

**Classification report:**

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| Died (0) | 0.810 | 0.891 | 0.848 | 110 |
| Survived (1) | 0.793 | 0.667 | 0.724 | 69 |

The model is **cautious**: recall for survivors is only 0.667, so it misses about
a third of them. That follows from the class imbalance — "died" is the safer
guess when uncertain. Lowering the 0.5 decision threshold would raise recall at
the cost of precision.

**What the model learned** (coefficients on scaled features, so sizes are
directly comparable):

| Feature | Coefficient | Effect |
|---|---|---|
| `Sex` | **+1.270** | being female strongly raised survival odds |
| `Pclass` | **−0.929** | a worse class lowered them |
| `Age` | −0.503 | older passengers fared worse |
| `SibSp` | −0.263 | larger families fared slightly worse |
| `Embarked_S` | −0.172 | small negative effect |
| `Fare` | +0.100 | nearly redundant with `Pclass` |

## Methodology notes

Three decisions worth calling out, because each one prevents a silently inflated
score:

1. **No data leakage from scaling.** `StandardScaler` is fitted on the
   *training data only* (`fit_transform`), then applied to the test set and to
   new passengers with `transform` alone. The same fitted scaler is reused in
   Phase 7 — never re-fitted.

2. **Model selection never touches the test set.** Logistic Regression is
   compared against two Decision Trees using **5-fold cross-validation on the
   training data**. Picking a model by test-set performance would mean the test
   set is no longer unseen.

3. **Fabricated labels removed.** The 418 rows with invented `Survived = 0`
   values are excluded, which *lowers* the apparent accuracy but makes it honest.

The cross-validation result was itself instructive. The unlimited-depth Decision
Tree scored **worst** despite being the most flexible model — left unrestricted
it memorises individual passengers. Capping depth at 3 forced general rules and
the score jumped, edging past Logistic Regression (0.8077 vs 0.7964). But that
gap is smaller than either model's own standard deviation (± 0.03), so the two
are statistically tied. Logistic Regression was chosen for its interpretable
coefficients, its probability outputs (needed in Phase 7), and its greater
stability (± 0.019 vs ± 0.031).

Phase 7 also **reproduces one prediction by hand** — multiply each scaled feature
by its weight, sum, add the intercept, apply the sigmoid, threshold at 0.5 — and
asserts the result matches `predict_proba()` to six decimal places. There is no
magic inside `.predict()`.

## Known limitation

The model predicts that a 5-year-old boy in 3rd class **dies** (11.0 % survival),
whereas children historically had high survival rates. The cause is that `Age`
enters as a single **linear** term, so it can express *"each extra year changes
the odds by a fixed amount"* but **not** *"children were prioritised."*

The fix is feature engineering rather than a fancier algorithm — for example:

```python
data["IsChild"] = (data["Age"] < 16).astype(int)
```

That is outside the scope of this assignment, but it is the honest explanation
for that particular prediction.
