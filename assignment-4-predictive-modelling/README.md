# Predictive Modelling with Pandas — Titanic Dataset

A complete, beginner-friendly machine learning pipeline built with **pandas**,
**matplotlib** and **scikit-learn**. The project ingests the Titanic passenger
dataset, cleans it, explores it, trains a Logistic Regression classifier,
evaluates it honestly on unseen data, and predicts survival for new passengers.

Every module is heavily commented so the code can be read as a tutorial.

---

## Quick start

```bash
# 1. Install the dependencies
pip install -r requirements.txt

# 2. Run the entire project
python main.py
```

> **Note:** the script opens matplotlib chart windows at the end of Phases 3,
> 6 and 7. Execution **pauses** at each one until you close the window. That is
> normal behaviour, not a hang.

Run it from inside the `A4` folder, because the data path
(`Data/train_and_test.csv`) is relative to the working directory.

## The seven phases

| Phase | What it does | Where it lives |
|-------|--------------|----------------|
| **1** | Load the CSV; show head, shape, info, columns, missing values | `preprocessing.load_and_explore_data()` |
| **2** | Drop useless columns, fill missing values, rename, one-hot encode | `preprocessing.clean_data()` |
| **3** | Statistics, grouped survival rates, correlations, 6 charts | `eda.run_eda()` |
| **4** | Select labelled rows, split X/y, train-test split, feature scaling | `preprocessing.prepare_model_data()` |
| **5** | Create and train Logistic Regression; compare models via cross-validation | `train.train_model()` |
| **6** | Accuracy, confusion matrix, classification report, overfitting check | `evaluate.evaluate_model()` |
| **7** | Predict survival for 6 invented passengers, with probabilities | `predict.predict_samples()` |

## About the dataset

`train_and_test.csv` is a pre-processed variant of the classic Titanic dataset —
**not** the standard Kaggle file. Notable quirks handled by the pipeline:

| Quirk | How it is handled |
|-------|-------------------|
| 19 columns named `zero`, `zero.1` … `zero.18`, all zeros | Dropped in Phase 2 (verified to sum to 0 before deleting) |
| Target column is misspelled `2urvived` | Renamed to `Survived` |
| `Passengerid` is just a row counter | Dropped — an ID has no predictive value |
| `Embarked` has 2 missing values | Filled with the mode (correct choice for a category) |
| `Sex` / `Embarked` already numeric-coded | Classified as binary / ordinal / nominal; `Embarked` one-hot encoded |
| No `Name`, `Ticket` or `Cabin` columns | Not present in this variant |

### ⚠️ Important data-quality finding

The file is the Kaggle `train.csv` (891 rows, **real** labels) stacked on top of
`test.csv` (418 rows whose labels are **deliberately hidden**). Whoever built it
filled those 418 unknown labels with `0`, so the data claims all 418 passengers
died — which is false; their outcome is simply unknown.

**Phase 4 therefore keeps only the first 891 rows.** Training on fabricated
labels would teach the model a false pattern and inflate the apparent accuracy.

Final feature set (8 features + target):

```
Age, Fare, Sex, SibSp, Parch, Pclass, Embarked_Q, Embarked_S  →  Survived
```

## Results

| Metric | Value |
|--------|-------|
| Rows used for modelling | 891 (of 1309) |
| Train / test split | 712 / 179 (80 / 20, stratified) |
| Model | Logistic Regression |
| Baseline (always guess "died") | 61.62 % |
| **Test accuracy (unseen data)** | **80.45 %** |
| Improvement over baseline | **+18.83 percentage points** |
| Train vs test gap | 0.31 pp → no overfitting |

**Confusion matrix (179 test passengers):**

|  | Predicted: Died | Predicted: Survived |
|---|---|---|
| **Actual: Died** | 98 (TN) | 12 (FP) |
| **Actual: Survived** | 23 (FN) | 46 (TP) |

**Classification report:**

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| Died (0) | 0.810 | 0.891 | 0.848 | 110 |
| Survived (1) | 0.793 | 0.667 | 0.724 | 69 |

The model is **cautious**: recall for survivors is only 0.667, meaning it misses
about a third of them. That is a consequence of the class imbalance — "died" is
the safer guess when uncertain. Lowering the 0.5 decision threshold would raise
recall at the cost of precision.

**What the model learned** (coefficients on scaled features):

| Feature | Coefficient | Effect |
|---|---|---|
| `Sex` | **+1.270** | being female strongly raised survival odds |
| `Pclass` | **−0.929** | a worse class lowered them |
| `Age` | −0.503 | older passengers fared worse |
| `SibSp` | −0.263 | larger families fared slightly worse |
| `Embarked_S` | −0.172 | small negative effect |
| `Fare` | +0.100 | nearly redundant with `Pclass` |
| `Embarked_Q` | +0.081 | negligible |
| `Parch` | −0.067 | negligible |

## Methodology notes

Three decisions worth highlighting, because each one prevents a silently
inflated score:

1. **No data leakage from scaling.** `StandardScaler` is fitted on the
   *training data only* (`fit_transform`), then applied to the test set and to
   new passengers with `transform` alone. The same fitted scaler is reused in
   Phase 7 — never re-fitted.

2. **Model selection never touches the test set.** Logistic Regression is
   compared against two Decision Trees using **5-fold cross-validation on the
   training data**. Picking a model by test-set performance would make the test
   set no longer unseen.

3. **Fabricated labels removed.** The 418 rows with invented `Survived = 0`
   values are excluded, which *lowers* the apparent accuracy but makes it honest.

The cross-validation result was itself instructive: the depth-3 Decision Tree
scored marginally higher (0.8077 vs 0.7964) — but the gap is smaller than either
model's standard deviation (± 0.03), so the two are statistically tied. Logistic
Regression was chosen for its interpretable coefficients, its probability
outputs, and its greater stability (± 0.019 vs ± 0.031).

## Known limitation

The model predicts that a 5-year-old boy in 3rd class **dies** (11.0 % survival),
whereas children historically had high survival rates. The cause is that `Age`
enters the model as a single **linear** term, so it can express *"each extra year
changes the odds by a fixed amount"* but **not** *"children were prioritised."*

The fix is feature engineering rather than a fancier algorithm — for example:

```python
data["IsChild"] = (data["Age"] < 16).astype(int)
```

This is outside the scope of the assignment but is the honest explanation for
that particular prediction.
